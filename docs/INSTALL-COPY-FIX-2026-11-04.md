## DBI 公开行为与实现范围

DBI 的[公开说明](https://github.com/rashevskyv/dbi#warnings)将转换或编辑内容带来的摘要及签名差异列为警告；其[默认配置](https://github.com/rashevskyv/dbi/blob/main/dbi.config)仍启用 `CheckHash`。因此，不能由“DBI 可以安装”推断关闭了哈希检查，也不能仅凭内容 ID 与摘要不同断言整个包不可用。公开仓库提供文档、配置和电脑后端，未提供可直接移植的 Switch 端安装源码。本轮参照公开行为实现兼容策略，没有声称移植 DBI 内部解析器。

EBF9 对应当前安装器的 `YatiInvalidNcaSha256`：实际 NCA SHA-256 的前 16 字节与原内容 ID 不同。对用户指定文件的只读检查确认存在这种差异；包分区和前导块校验通过，原文件没有修改。这能解释 EBF9，但不证明另一个 CNMT 失败具有相同原因。

手动安装增加“兼容转换包（摘要差异以警告显示）”，默认勾选。配套仍读取并计算实际 NCA 摘要，在差异处记录条目、原内容 ID 和完整实际 SHA-256，然后继续原安装流程；保留原内容 ID 关联，不单独重命名 NCA。成功结果和任务记录显示警告，详情可复制，重试／跳过流程不会重新安装已经完成的项目。

协议字段 `ncaHashPolicy` 支持 `strict` / `warn`，缺省为严格。新能力为 `install.hash-warning.v1`；旧配套遇到兼容请求明确提示更新，取消勾选后可继续原严格安装。`titles.install.plan` 始终拒绝兼容策略。现有来源摘要、长度、同句柄安装前核对、格式与签名检查继续执行；兼容选项仅改变内容 ID 摘要差异的处理。无法解析的内容仍会报错。

## CNMT 后续审查

此前固定 CTR 密钥槽及头副本的修复保留。本轮又补充：

- 将密钥代次限制在锁定实现的软件密钥表范围内，拒绝越界后再进入解密逻辑。
- 固定解析修订标识 `cnmt-v3`，附带 NCA 偏移、分区、加密／哈希类型、密钥代次、PFS 偏移和读到的 magic；不输出密钥。
- 失败文本直接包含实际配套构建来源。安装内部预检保留完整 CNMT 错误，避免被通用“解析安装包失败”覆盖。

当前生产源码中，PFS magic 不符的阶段为 `Pfs0Magic`；读取失败阶段为 `ReadPfs0Header`，不能仅用用户复述的旧字符串确定真实解密失败原因。用户已确认旧版 `+6e266a654443`，不再将“未更新 NRO”作为已证实原因。**本轮没有复现或完成该用户包的真机验收，原 CNMT 问题尚待新诊断确认。**

## Windows 复制

- “连接诊断”可复制完整诊断信息及配套完整版本；诊断包含当前或离线资料来源、两端版本、环境、能力、安装提示及最近日志。
- 安装页可复制安装信息和所选项目的完整校验提示。
- 普通显示文字可右键选择“复制文本”，被视觉截断的文字也复制完整内容；列表支持 Ctrl+C。编辑框、密码框和表格原生复制行为继续由对应控件处理。
