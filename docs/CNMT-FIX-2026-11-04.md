# 2026-11-04 CNMT 解析与脚本入口修复

用户报告 NSP 预检失败：`ReadPfs0Header Result=000000000000A5F9`，随后 `fsp-srv` 回退返回 `00000000BCE99002`。本轮没有读取、修改用户的游戏包或密钥，也没有部署 NRO、安装内容或操作真实设备。

## 原因与修改

原用户态解析器使用 `key_area[section_index]` 解密 AES-CTR 分区，将分区编号当作密钥槽。常见 CNMT 位于分区 0，而 CTR 使用固定槽 2；错误密钥产生无效 PFS0 magic，返回本项目的 `NspBadMagic`（A5F9）。[hactool 原作者实现](https://github.com/SciresM/hactool/blob/master/nca.c#L507)使用相同的固定槽规则。不能仅凭回退结果 BCE99002 推断主机缺少何种文件或补丁。

- 将解析器移入正式 `companion/source/yati/nx/cnmt.cpp`，固定 CTR 密钥槽，并在副本上解密，保留调用方原始头。
- 校验 NCA、分区、PFS0 文件表、名称终止、CNMT 扩展头、内容条目、元内容条目和末尾摘要的长度；短读与错误继续向上传递，失败不发布部分解析结果。
- 安装路径重新读取源包头，避免已安装内容的头与源包加密参数混用；顺序流和 NCZ 保留已解压暂存内容的原路径，不回读已消费的流或把压缩字节当作 NCA。
- 原函数只存在于被忽略的生成目录中，旧对应源码不能重建该路径。本轮通过正式覆盖层和准备脚本还原，干净目录目标构建另外验证。

## 两站资源搜索

Gamer520 的首次 403 实际包含匿名 Cookie 初始化和同一搜索 URL 的重载指令。旧实现直接结束请求；现仅在适用 Cookie、明确同 URL 重载且无交互验证时重载一次，两次请求共用 25 秒和 4 MiB 预算。普通限制页、第二次 403、换域、变更关键词或验证码仍停止，不执行网页脚本。

NS 头号玩家的旧 `.com` 域名现为官方公告。应用从公告提取可确认的品牌域名，尝试备用入口并处理有限重定向，再按公开前端的正常匿名会话流程搜索 Switch 游戏；保留匿名 Cookie 于本次 HTTP 客户端，不导入浏览器会话或账号信息。验证计算限制为 2 秒，并支持取消。错误响应结构与异常列表不会误报为没有资源。

使用应用实际 HTTP 工厂验证公开文章查询：Gamer520 的 `PICO PARK` 返回 2 条、`死亡细胞` 返回 3 条；NS 头号玩家的 `PICO PARK`、`萌猫公园`、`死亡细胞` 分别返回 2、2、1 条。只查询文章，没有下载游戏。原站可能按正文匹配相关条目，结果数量会随网站变化。浏览器站内搜索会重新核对官方入口并保留关键词，另提供公开索引与官方公告入口。
