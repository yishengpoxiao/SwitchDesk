# 2026-11-04 安装 81F9 修复

用户随后选择直接调用 DBI；Windows 新增的独立入口与用法见[通过 DBI 安装](DBI-INSTALL.md)。下文保留自有配套修复基线 `97d1f3da0899` 的验证，后续交付另带最新统一来源标识。

用户在上一轮 `+64fcf07b855d` 开发包上遇到 `Result=00000000000081F9`。电脑日志显示预检已经完成，失败发生在安装开始后；不能继续把它当作先前的 CNMT 解析错误或 EBF9 内容摘要差异。

## 原因

锁定安装器中，81F9 对应 `Result_NcaFailedNcaHeaderHashVerify`（模块 505、描述 64）。虽然枚举名包含 Hash，这里实际验证的是 NCA 固定头的 RSA2048-PSS-SHA256 签名：原始头和分发类型变体都未通过才返回此值。[锁定上游实现](https://github.com/NaGaa95/sphaira/blob/338348e74b6d278bc570a9be5373d25197bf6c8d/sphaira/source/yati/nx/nca.cpp#L166)。

上一轮兼容模式只覆盖完整 NCA 摘要与内容 ID 的差异，仍将所有头签名校验失败视为安装错误，因此未覆盖这次情况。[DBI 公开说明](https://github.com/rashevskyv/dbi#warnings)将转换或编辑包的签名差异列为警告；本轮参照这一公开行为补齐明确的签名兼容策略。签名校验失败本身不能证明包被正确转换，也不能证明它一定损坏。

## 修改

- 手动安装选项改为“兼容转换包（签名与摘要差异以警告显示）”，两类警告都记录至安装详情、任务历史及复制信息；完成但含警告的项目不会被后续重试重复安装。
- 协议独立增加 `ncaSignaturePolicy`，支持 `strict` / `warn`，缺省严格；新能力为 `install.signature-warning.v1`。旧配套不能静默接受扩大的兼容语义，电脑端明确要求更新。
- 继续执行实际 RSA 校验，仅在明确启用签名兼容且结果精确为 81F9 时转为 `NcaHeaderSignatureMismatch` 警告，附条目、原始签名覆盖范围的 SHA-256 和原校验结果。使用头副本验签，失败分支不污染安装头。
- 严格模式继续拒绝签名差异；管理安装计划强制严格。未知签名策略、公钥代次越界、解密／格式／读取错误不会被转为警告。NCA 摘要计算、来源摘要和长度约束继续执行。
- 严格模式下的 81F9 返回明确的头签名错误说明，避免界面仅显示通用十六进制错误。
