## 修复内容

| 范围 | 问题及修复 |
| --- | --- |
| USB 取消 | 取消可能先于原生 I/O 提交，单次中止会落空，随后等待长超时。取消后持续中止当前操作，等工作线程及中止循环退出后才允许同方向下一次传输。排队任务取消不影响在途操作。 |
| CNMT 回退 | 系统服务回退未核对实际读取字节数和完整表边界，夹具复现仅一字节 CNMT 被接受。现在与用户态共用边界及精确读取检查；只选择唯一 CNMT，容许其他普通文件，失败保留原输出。 |
| 游戏状态 | 获取组件清单失败不再被误标为游戏已归档或卡带未插入，明确保留读取错误。 |
| 存档完成状态 | 主机已确认写回后，电脑完成日志失败单独提示警告，保留 Recovery 位置，不再将完成记录重写为失败。后续复查与列表刷新也与已完成的写回区分。 |
| FTP 文件名 | MLSD 按首个分隔空格读取完整文件名，修复含 `; ` 的文件名截断；普通 Unix 列表文件名中的 ` -> ` 不再被当作链接后缀。 |
| FTP 错误与取消 | 空目录上传遇到创建失败时核对目标是否已存在，不能无条件报告成功；普通命令等待应答时取消会关闭已失步连接，避免下一命令错用迟到应答。 |
| 文件夹上传 | USB 和 FTP 枚举本地目录遇到无访问权限时明确报错，不再静默遗漏目录中的内容。 |
| 资源搜索 | 搜索中改变关键词、类型或来源会取消旧请求并提示重新搜索；取消或过期查询不会覆盖当前结果的来源约束。自有索引逐个隔离故障，一个坏来源不阻断其他来源，全部失败也不会误报没有资源。 |
| 内容索引 | 拒绝部分 HTTP 响应、异常范围、长度不完整及非法条目。统一限制索引读取大小；更新页遇到损坏索引时保留旧缓存与原获取时间。 |

FTP 解析依据 [RFC 3659](https://www.rfc-editor.org/rfc/rfc3659)，原生取消语义核对了 [WinUsb_AbortPipe](https://learn.microsoft.com/en-us/windows/win32/api/winusb/nf-winusb-winusb_abortpipe)。CNMT 目录处理另对照 [Atmosphère 的元数据读取](https://github.com/Atmosphere-NX/Atmosphere/blob/master/libraries/libstratosphere/source/ncm/ncm_content_meta_utils.cpp)。
